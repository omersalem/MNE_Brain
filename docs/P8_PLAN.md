# P8 Plan: Live Troubleshooting and Root-Cause Orchestration

P8 provides a fast, bounded path from a reported Ministry symptom to an evidence-ready reasoning handoff.

1. Reconcile all 32 P7 operational bindings without changing canonical knowledge.
2. Register eight diagnostic families: branch, VPN, web publishing, DNS/AD, Exchange, VMware, firewall/security, and storage/backup/switching.
3. Require one exact scenario and one exact active binding.
4. Select no more than three read-only checks, with explicit evidence objectives.
5. Accept only fresh attributable trust-5 evidence and keep the handoff below 6,000 characters and approximately 1,500 tokens.
6. Expose non-connecting status and plan endpoints to the presentation-only GUI.
7. Use the P7 runner only through an explicit owner-gated in-memory live session.
8. Preserve all disabled automation and remediation controls.

P8 does not automatically diagnose from management reachability. The evidence-bounded AI reasoning stage must state confidence, unknowns, the next check, and any proposed action.
